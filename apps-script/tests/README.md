# Перевірка коду Apps Script на місці

`.gs` не запустиш ніде, крім Google — а перевіряти треба саме те, що вже
двічі підводило нас тихо, без жодної помилки на екрані.

Тому тут пісочниця: підміняємо `SpreadsheetApp`, `LockService`,
`PropertiesService` і функції з `Code.gs`, після чого ганяємо справжній код
`ManagerTransfer.gs` як звичайний JavaScript.

```
node apps-script/tests/transfer-tests.js
```

## Що перевіряємо і чому саме це

**Інцидент 25.09.2026.** User змінив менеджера у 10 клієнтів — переїхало 3.
Причина: кожен перенос бере спільний замок і робить десятки секунд важкої
роботи, а сусідні редагування чекають рівно 20 секунд і тихо здаються.
Результат `transferLeadRow_` ніхто не читав, тож сім клієнтів не переїхали й
не лишили сліду.

Тест `десять змін підряд` відтворює це: замок вдається кожен третій раз.
На коді до виправлення він дає рівно ті самі 3 з 10.

**Доповнення того ж дня.** Перший запуск звірки на бойових даних показав 113
розбіжностей — і більшість з них виявились не збоєм синхронізації, а тим, що
у менеджера просто немає таблиці (у Зингель Олени її так і не завели). Такі
рядки нікуди класти, а звірка щоразу бралася б за них знову, з'їдаючи ліміт і
не доходячи до тих, кого справді можна полагодити. Тепер вони рахуються
окремо, з підказкою, чого бракує.

Заразом виявилось, що випадачка редактора Apps Script показує лише функції
БЕЗ аргументів — тож `resyncManagerAssignments(false)` звідти не запустити
взагалі. Для цього є `resyncManagerAssignmentsApply`.
