# 📊 L-TEX | Розширена статистика клієнтської бази

Google Apps Script для таблиці **LTEX_Клієнти_CRM_v2**, який будує гнучку
багаторівневу аналітику клієнтської бази поверх наявних аркушів менеджерів.

## Що ви отримаєте

| Аркуш | Що показує | Оновлення |
|---|---|---|
| **📋 Реєстр** | Усі клієнти з усіх аркушів одним плоским списком: дата, рік, місяць, область, місто, ім'я, телефон, статус, канал, категорія, менеджер + посилання на аркуш/рядок джерела. Має фільтр — можна сортувати й відбирати прямо тут. | Скриптом (меню / автоматично) |
| **📍 Області × Місяці** | Матриця: області в рядках, місяці в колонках, теплова мапа. Фільтри згори: **Рік / Статус / Менеджер**. | Формули — миттєво |
| **👥 Менеджери × Місяці** | Та сама матриця в розрізі менеджерів. Фільтри: **Рік / Статус / Область**. | Формули — миттєво |
| **🌳 Ієрархія** | Розгорнутий звіт: **область → місяць → список клієнтів** з датами, телефонами, статусами. Області згорнуті у групи рядків — натискайте «+» ліворуч. | Скриптом |
| **📊 Дашборд** | Загальні показники (всього, поточний/попередній місяць, дублі телефонів, статуси), динаміка по місяцях з барами, топ областей, канали та менеджери по роках. | Формули — миттєво |
| **🔀 Зведена** | Звичайна зведена таблиця Google Sheets поверх Реєстру. Натисніть «Змінити» та **самостійно компонуйте** рядки/стовпці/значення/фільтри з будь-яких полів. | Живе джерело даних |

## Встановлення (одноразово, ~2 хвилини)

1. Відкрийте таблицю CRM → меню **Розширення → Apps Script**.
2. У редакторі створіть файл (або використайте `Код.gs`) і вставте туди
   **повний вміст** файлу [`ltex-statistics.gs`](./ltex-statistics.gs).
3. Збережіть (Ctrl+S) і перезавантажте вкладку з таблицею.
4. З'явиться меню **«📊 L-TEX Звіти»** → натисніть **«🔄 Оновити всі звіти»**.
   При першому запуску Google попросить надати дозволи — підтвердьте
   (скрипт працює лише всередині цієї таблиці).
5. За бажанням: **«⚡ Увімкнути автооновлення»** — Реєстр та Ієрархія
   перебудовуватимуться автоматично після змін у базі (зокрема коли бот
   додає нових клієнтів через API; не частіше, ніж раз на 3 хв), а повна
   перебудова всіх звітів виконуватиметься щогодини. Формульні звіти
   (матриці, дашборд, зведена) підхоплюють оновлений Реєстр миттєво.

## Як скрипт знаходить дані

Скрипт сканує **всі аркуші** таблиці й вважає аркушем із клієнтами той, де
в перших 6 рядках знайдено колонки **Ім'я, Телефон і Дата** (порядок колонок
не важливий, синоніми на кшталт «ПІБ», «Тел», «Дата звернення» теж
розпізнаються — список синонімів у `CFG.ALIASES`). Додатково підхоплюються
колонки Область, Місто, Статус, Канал, Категорія, Менеджер.

- Якщо колонки «Менеджер» на аркуші немає — менеджером вважається **назва
  аркуша** (як у вкладок Гуменюк, Дунас тощо).
- Області нормалізуються: «київська обл.», «Київська область» → «Київська»;
  порожнє значення → «Не вказано».
- Дата розпізнається і як дата таблиці, і як текст `дд.мм.рррр` або
  `рррр-мм-дд`. Рядки без дати потрапляють у групу «Без дати».

Аркуші звітів та стара «Статистика» ігноруються автоматично.

## Поради

- **Своя компоновка**: найзручніше — аркуш «🔀 Зведена»: клацніть таблицю →
  «Змінити» → перетягуйте поля (Менеджер, Область, Місяць, Статус, Канал,
  Категорія, Рік…) між рядками, стовпцями, значеннями та фільтрами.
  Скрипт **не перезаписує** вашу компоновку; повернути стандартний вигляд —
  меню «♻️ Скинути зведену таблицю».
- **Списки клієнтів з датами**: «🌳 Ієрархія» (по областях і місяцях) або
  «📋 Реєстр» із фільтром (будь-який зріз).
- Якщо додали нового менеджера чи з'явився новий місяць — натисніть
  «🔄 Оновити всі звіти» (або зачекайте на автооновлення): списки рядків
  у матрицях і дашборді перебудуються.

## Обмеження

- Реєстр перебудовується скриптом, тому між зміною бази та оновленням
  Реєстру може минути до 3 хв (при увімкненому автооновленні). Усі
  формульні звіти рахуються з Реєстру миттєво.
- Нові області/менеджери/місяці з'являються як нові рядки та колонки
  звітів під час повної перебудови (щогодини або з меню).
- Лічильник «Дублі телефонів» на дашборді перераховується під час
  оновлення звітів (не формулою) — щоб не сповільнювати таблицю.
