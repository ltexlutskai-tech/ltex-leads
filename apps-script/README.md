# L-TEX CRM — перепризначення менеджера (v6.9)

Модуль `ManagerTransfer.gs` додає в Apps Script-проєкт CRM автоматичний
**перенос контрагента між менеджерами**: змінюєш менеджера в колонці **K**
аркуша `🔒 2026` — рядок сам зникає з таблиці попереднього менеджера,
зʼявляється в таблиці нового, а обидва отримують повідомлення у Viber.

## Що відбувається при зміні менеджера

1. Рядок з цим `ID` **видаляється** з файлів усіх інших менеджерів
   (в тому числі тих, кого позначено як неактивних).
2. Дані, які менеджер уже встиг заповнити у своєму файлі —
   `Перший контакт`, `Активність`, `Статус дії`, `Оновлений статус`,
   `Коментар` — **не губляться**: підтягуються в головну таблицю
   (якщо там порожньо) і їдуть у файл нового менеджера.
3. Рядок додається у файл нового менеджера (дублі з тим самим `ID`
   прибираються автоматично).
4. **Новому менеджеру** у Viber:
   `📥 Вам передано контрагента! … ⚠️ Потрібно актуалізувати інформацію та продовжити роботу.`
5. **Попередньому менеджеру**: `📤 Контрагента передано іншому менеджеру… Рядок прибрано з вашої таблиці.`
6. Керівникам (`notifyOwners`) — коротка довідка «було → стало»,
   а в головний файл пишеться прихований журнал `_transfers`.
7. Якщо налаштований місток `LTEX_CRM_URL` — зміна менеджера їде і в нашу систему.

Перше призначення менеджера (раніше клітинка була порожня) переносом
**не вважається** — там працює звичне сповіщення «Новий клієнт призначено тобі!»
з `onEdit` у `Code.gs`.

## Встановлення

1. В редакторі Apps Script проєкту CRM створи новий файл скрипта
   **`ManagerTransfer`** і встав туди вміст `ManagerTransfer.gs`.
2. Запусти один раз функцію **`installManagerTransferTrigger()`**
   (дозволи доступ, якщо запитає).
3. Перевір: `Тригери` → має зʼявитись `onMainEditTransfer` для головної таблиці.

Існуючий код чіпати не потрібно — `onEdit(e)` у `Code.gs` лишається як є.
Модуль працює через власний тригер і використовує наявні
`getManagers()`, `syncToManager()`, `sendViber()`, `notifyOwners()`,
`pushLeadToLtexCrm()`, `generateId()`.

Прибрати тригер: `removeManagerTransferTrigger()`.

## Ручні інструменти (запуск з редактора)

| Функція | Що робить |
|---|---|
| `reassignLead("LTEX-…", "Дунас Богдан")` | Перепризначити конкретного ліда за ID |
| `reassignLeadByPhone("0671234567", "Дунас Богдан")` | Те саме за номером телефону |
| `cleanupManagerFilesFromMain(true)` | **Перевірка**: показує, скільки «чужих» рядків у кожного менеджера, нічого не змінює |
| `cleanupManagerFilesFromMain(false)` | Прибирає з файлів менеджерів рядки, які за головною таблицею належать іншому |

`cleanupManagerFilesFromMain` варто запустити один раз після встановлення —
вона наведе лад після попередніх ручних перенесень. Рядки, `ID` яких немає
в головній таблиці, вона **не видаляє** — лише рахує у звіті.

## Налаштування у файлі

| Константа | За замовчуванням | Призначення |
|---|---|---|
| `TRANSFER_LOG_SHEET` | `_transfers` | Назва аркуша-журналу перенесень |
| `TRANSFER_MAX_ROWS` | `50` | Ліміт рядків за одне редагування (захист від таймауту при вставці великого діапазону) |
| `TRANSFER_PUSH_TO_CRM` | `true` | Чи надсилати зміну менеджера в L-TEX CRM |

## Тести

Логіку переносу перевірено на емуляції Google Apps Script (без доступу до реальних таблиць):

```bash
node apps-script/test/transfer.test.js
```

Покрито: перенос із збереженням даних обдзвону, відсутність зайвих сповіщень
при першому призначенні, ігнорування редагувань інших колонок, прибирання
дублів, забирання рядка в неактивного менеджера, `reassignLead`
та `cleanupManagerFilesFromMain`.
